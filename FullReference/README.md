# 完整参考底包增量构建

这是与 `NativeCompanion` 分开的完整原生客户端构建路径。`NativeCompanion` 是 Swift + WebKit 重写，不能声称与原版 React Native 客户端功能等价。此路径使用用户提供、已实车验证可以连接的完整参考 IPA，不发布其二进制到公开源码仓库。

参考输入：`LX_Music_1.8.4_CarPlay_v11_native_now_playing(1).ipa`，SHA256 `ca6e8331816d69f42e41a22bdb10a3efc18df66b58b0a4e1cda4a900e2e1eb9e`。

保留参考包的原生主程序（只增加动态库加载命令并重新签名）、Hermes 框架、原始 `CarPlaySupport.dylib`、原生 TrackPlayer/DSP 音效、图片、字体、全部旧资源和容器标识。使用仓库完整 React Native 源码生成匹配 Hermes 96 的完整业务包，以接入本仓库已有的 CarPlay 歌单事件桥；不会替换成网页或删减依赖。

新增 `LXFullCarPlay.dylib` 提供 CarPlay 音乐库缓存与选歌桥，不接管原参考包的 AppDelegate 启动和手机窗口。连接/断开仍调用原始库实现，追加音频标准回调转发和连接日志。原始库连接成功后，扩展其菜单；若扩展失败，调用原始菜单实现回退。选歌交给原有 JS 播放器与音源解析，不创建第二个播放器；音乐库在本机缓存，可在车机冷启动时显示；重复点击只保留最后一次待执行选歌。

连接日志在 iOS“文件 → 我的 iPhone → LX 音乐 → LX-CarPlay-Connection.json”中，可直接分享。仅记录构建号、容器标识、iOS、回调阶段、缓存歌单数及固定错误，不包含账号令牌、音源脚本或播放地址。

该构建沿用参考包的原生手机界面。之前 `NativeCompanion` 的首页/房间聊天等网页重设计没有被冒称已移植到此原生客户端。这两条构建路径保留在仓库中，不删除已有实现。

工作流仅构建公开源码的扩展与完整 JS 包。打包工具从用户本地参考包读取完整底包，核对固定 SHA256 后合成。每个未主动修改的旧文件逐字节验证，导出保留清单。不会通过塞入无用资源来增加体积。

编译、缓存/事件测试与包内保留验证不能替代实车验证。物理 CarPlay 连接仍需用户复测。
